# Проверка повторной сборки Alpine

10 сентября 2026 года, тот же HP 260 G4 / Pentium Gold 6405U. Проверка выполнена после [первоначального запуска Alpine](report.md), без замены рабочего контейнера.

## Изменение рецепта

Компиляция ONNX перенесена в `Dockerfile.onnx-alpine`, запускаемый через `scripts/prepare-onnx-alpine.sh`. На HP скрипт автоматически выбрал `amd64` и все четыре логических CPU. Существующий C++-слой целиком использован из кэша; повторной часовой компиляции не было. Экспортирован комплект `.onnxruntime/amd64/` с библиотеками, лицензиями, версией, архитектурой, списком пакетов и SHA-256.

`Dockerfile.alpine` теперь проверяет и копирует этот комплект. Теги базовых Alpine и Go дополнены digest. Узкое исправление GCC 15 в `logging.cc` сохранено в отдельном рецепте ONNX.

## Результаты

| Проверка | Результат |
|---|---|
| Сборка отдельного образа `gigaam-service:alpine-rebuild-check` | Успешно, 3,536 с |
| Повторная сборка того же образа с кэшем | Успешно, 0,371 с |
| Цель `test`: `go test ./...` и `go vet ./...` | Успешно; вся цель с установкой FFmpeg и экспортом — 86,441 с |
| SHA-256 ONNX и Go-бинарника в новом и рабочем образах | Совпали |
| Нет локального комплекта ONNX | Сборка отклонена |
| Другая архитектура или версия, с пересчитанными SHA-256 | Сборка отклонена |
| Изменён файл библиотеки | Сборка отклонена при проверке SHA-256 |
| ID контейнера, время старта, RestartCount до и после | Не изменились; `running healthy` |

Полные числовые результаты: [rebuild-results.json](rebuild-results.json). Отрицательные проверки использовали временные копии библиотеки; рабочий комплект не изменялся. Дополнительно на Mac проверены синтаксис shell-скрипта и его поведение с подставным Docker: ошибка экспорта сохраняет старый комплект, успешный экспорт оставляет предыдущую копию, неверные аргументы отклоняются.

Это проверка использования готовой библиотеки и существующего Docker-кэша. Чистая сборка всех зависимостей без кэша заново не проводилась. Новая транскрибация для этого изменения не измерялась: исполняемый файл и ONNX совпали с уже проверенными, результаты распознавания сохранены в основном отчёте. Быстрое время сборки не относится к первичной загрузке моделей или первой компиляции Go/ONNX.

## Логи на HP

В `~/gigaam-service/`:

- `onnx-prepare.log` — подготовка библиотеки из кэша;
- `alpine-rebuild.log`, `alpine-rebuild-repeat.log` — сборки сервиса;
- `alpine-rebuild-tests.log` — Go-тесты и vet;
- `alpine-rebuild-reject-*.log` — ожидаемые отказы;
- `alpine-rebuild-results.json` — результаты и хеши.

Обычная пересборка и порядок обновления зависимостей: [docs/alpine-build.md](../../docs/alpine-build.md). APK-репозитории остаются обновляемыми; для сохранения проверенной ONNX-библиотеки нужно хранить `.onnxruntime/amd64/` независимо от Docker-кэша.
