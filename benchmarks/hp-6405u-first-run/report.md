# Первый запуск GigaAM на HP 260 G4

10 сентября 2026 года. Сервис установлен и оставлен работающим на Ubuntu мини-ПК. Проверены готовность модели, два реальных запроса и доступ с Mac через SSH-туннель.

## Система и конфигурация

- По `lscpu`: **Pentium Gold 6405U, 2,4 ГГц**, 2 ядра / 4 потока. Ранее предполагался настольный G6405; фактическая модель другая. SSE4.1/4.2 есть, AVX/AVX2/VNNI нет.
- Ubuntu 24.04.2 LTS, Linux 6.11.0-17, x86-64. ОЗУ 7,58 ГиБ. SSD WDC PC SN520 128 ГБ, но раздел `/` около 55 ГиБ.
- Установлены Docker Engine 29.8.0, Buildx и Compose 5.5.1 из официального apt-репозитория Docker. ОС не переустанавливалась; обновление всех пакетов не выполнялось.
- Debian-образ, готовый ONNX Runtime 1.29.0 для amd64, FP32 RNNT, 2 потока ONNX, 1 запрос одновременно. ONNX из исходников не собирался.
- Исходники с текущими локальными изменениями перенесены в `/home/dmitry/gigaam-service`. Git push/commit для этого не выполнялся. Отдельный API-ключ создан непосредственно на мини-ПК в `.env` с правами 600.
- Только на мини-ПК максимальный файл ограничен **1 ГиБ**. Стандартный лимит проекта 20 ГиБ не изменён. Сервис проверяет максимальный разрешённый размер, WAV на 4 часа и резерв перед каждым запросом; для стандартного лимита нужно 20,93 ГиБ свободного места, после сборки осталось около 17 ГиБ.

## Проверки и измерения

Вход — первые 30 секунд WAV из существующего теста лекции, PCM16 mono 16 кГц, 960 044 байта. Один запрос после запуска и один повторный, последовательно. Клиент выполнялся на мини-ПК; нагрузочного мониторинга и измерения пиков CPU не было.

| Первый запрос целиком | 12,57 с |
| Повторный запрос целиком | 12,46 с |
| Инференс первого / повторного запроса | 12,13 / 12,20 с |

| Записываемый слой контейнера по Docker | 8192 байта |
| Свободное место раздела после теста | около 17 ГиБ |

Docker использует своё представление размера образа и кэша, между которыми могут быть общие данные; эти числа нельзя просто складывать. Это не измерение прироста физического места от одного контейнера и не прямое сравнение размера с прежним Docker Desktop на M4.

Память в таблице — показание Docker Stats, исключающее часть файлового кэша. Сырой cgroup memory.peak составил 2 399 842 304 байта и включает кэш; он не равен пику рабочего набора. После теста на хосте оставалось 4,1 ГиБ доступной памяти, использовано 5,2 МиБ swap (на старте 0). CPU сразу после запроса ещё отражает нагрузку, поэтому показание 23,49% в сырых результатах не названо простоем.

Оба ответа — HTTP 200, по 565 символов, полностью одинаковые строки. В логах два успешных `stage=complete`, по два ASR-фрагмента. **Работоспособность готового ONNX Runtime с этой моделью на 6405U без AVX подтверждена**. На этом коротком фрагменте скорость примерно в 2,4 раза выше реального времени; длинные лекции и INT8 на мини-ПК пока не измерялись. Сырые метрики: [results.json](results.json). Ручного эталона для оценки точности нет.

Контейнер healthy, политика перезапуска `unless-stopped`; API слушает только `127.0.0.1:8080` мини-ПК. Авторизованный `/v1/models` проверен как на мини-ПК, так и с Mac через туннель. Временные файлы запросов удалены.

## Использование

На мини-ПК:

```bash
cd ~/gigaam-service
sudo docker compose -f compose.yaml ps
sudo docker compose -f compose.yaml logs -f asr
```

На Mac сейчас создан временный туннель на `http://127.0.0.1:18082`. Он зависит от SSH-соединения. Если соединение закрыто, открыть туннель заново в отдельном терминале и оставить его работающим:

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:18082:127.0.0.1:8080 dmitry@192.168.0.36
```

В другом терминале Mac получить ключ в переменную без вывода в терминал и отправить локальный файл (заменить путь):

```bash
gigaam_key=$(ssh dmitry@192.168.0.36 \
  "sed -n 's/^GIGAAM_API_KEY=//p' ~/gigaam-service/.env")
printf 'header = "Authorization: Bearer %s"\n' "$gigaam_key" |
  curl --silent --show-error --fail-with-body --max-time 5700 --config - \
    http://127.0.0.1:18082/v1/audio/transcriptions \
    -F 'file=@/absolute/path/to/video.mp4' \
    -F 'model=gigaam-v3-e2e-rnnt' \
    -F 'response_format=text' -o transcript.txt
unset gigaam_key
```

Серверные результаты теста находятся в `~/gigaam-service/first-run-results.json`, лог — `first-run-server.log`, тексты — `first_request.txt` и `warm_request.txt`. Ключи, пароли и распознанные тексты в этот отчёт не включены.
