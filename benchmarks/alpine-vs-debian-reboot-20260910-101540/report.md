# Повторные замеры Debian / Alpine после перезагрузки

10 сентября 2026 года. Использованы ранее собранные образы; исходные файлы сервиса и параметры инференса не менялись. Предыдущие результаты сохранены в [первом отчёте](../alpine-vs-debian/report.md).

Alpine потребляет примерно на **32,8% меньше ОЗУ в простое** и имеет образ на **26,5% меньше**. В этой серии медиана инференса Alpine на общем WAV ниже на **8,3%**, а на видео выше на **3,1%**. Общего устойчивого преимущества в скорости не подтверждено: разброс и замедление к концу серии сохранялись даже без свопа. Это не позволяет объяснить прежние различия только свопом.

## Состояние памяти

- На старте: `10:15  up 8 mins, 2 users, load averages: 5.47 7.47 5.50`.
- Своп macOS: максимум **0.00 МиБ** за всю серию. Прирост swapins / swapouts: **0 / 0**.
- Уровни давления памяти macOS за серию: `[1, 2]` (1 — нормальный, 2 — повышенный). Замеров с повышенным уровнем: 3. Во время именно измеряемых запросов: `[1]`. Краткое повышение в начале первого запуска совпало с подготовкой и прогревом, который исключён из медиан скорости.
- Компрессор macOS занимал **3.85–6.23 ГиБ**. Отсутствие свопа не означает отсутствие сжатия памяти или фоновой нагрузки.
- Linux VM: максимальные счётчики pswpin / pswpout — **0 / 0 страниц**. Проверялись перед серией и после каждого контейнера.
- Своп, давление памяти, компрессор и load average macOS записывались примерно каждые 5 секунд в `host-memory.jsonl`.

Кроме трёх повышенных значений в периодической выборке, отдельный снимок после последнего контейнера и итоговый снимок перед восстановлением сервиса показали уровень 2; они находятся в `environment.json`. После восстановления основной сервис здоров, уровень памяти при контрольной проверке вернулся к 1. Во время измеряемых запросов периодический монитор зафиксировал только уровень 1. Результаты получены без свопа, но не без сжатия памяти и фоновой нагрузки.

## Протокол

- Apple M4, 16 ГиБ RAM; Docker Desktop, Linux ARM64, 10 vCPU / около 7,75 ГиБ RAM для VM. Хранилище Docker — внешний APFS-диск Goida.
- Те же RNNT FP32, ONNX Runtime 1.29.0, четыре потока. ID обоих образов совпали с предыдущим тестом.
- Входы: то же видео с аудио 462,016 с и общий PCM16 mono 16 кГц WAV из предыдущей серии. SHA-256 входов и ID образов — в `environment.json`.
- Для каждого входа три пары Debian/Alpine. Порядок менялся: WAV — D/A, A/D, D/A; видео — A/D, D/A, A/D.
- Для каждого запуска новый контейнер: ожидание готовности, 12 с простоя, полный первый запрос для прогрева, пауза 2 с, один измеряемый запрос, затем пауза 2 с и 12 с простоя. Всего 12 контейнеров и 24 запроса.
- По одному тестируемому контейнеру одновременно; основной сервис остановлен на время серии и восстановлен после неё. Пересборок и других контейнерных нагрузок во время замеров не было. Остальные приложения macOS не закрывались.

## Память и диск

| Метрика | Debian | Alpine |
|---|---:|---:|
| Образ с моделями | 1359.1 МиБ | 999.4 МиБ |
| ОЗУ после загрузки, медиана 6 запусков | 1332.1 МиБ | 895.0 МиБ |
| ОЗУ после запросов, медиана | 1452.1 МиБ | 1013.9 МиБ |
| Максимальный наблюдавшийся пик ОЗУ | 1553.0 МиБ | 1089.6 МиБ |
| RSS процесса после загрузки, медиана | 1344.9 МиБ | 916.2 МиБ |
| Максимальный наблюдавшийся RSS процесса | 1489.3 МиБ | 1034.7 МиБ |
| Записываемый слой после очистки запросов | 0 байт | 0 байт |

ОЗУ — cgroup `memory.current − inactive_file`, как в Docker stats; это не суммарная память Docker VM. RSS взят из `/proc/1/status`. Интервал выборки: 0,5 с плюс время docker exec; короткие пики могут быть пропущены. Размер образа — несжатые слои по Docker, без сборочного кэша; это не прирост физического Docker.raw. При обработке временно нужны место под входной файл и WAV.

## Скорость: измеряемые запросы после прогрева

| Вход | Пара | Debian, инференс | Alpine, инференс |
|---|---:|---:|---:|
| Общий WAV | 1 | 29.277 с | 27.313 с |
| Общий WAV | 2 | 29.786 с | 26.718 с |
| Общий WAV | 3 | 32.453 с | 33.064 с |
| **Общий WAV** | **Медиана** | **29.786 с** | **27.313 с** |
| Видео | 1 | 27.107 с | 27.804 с |
| Видео | 2 | 30.267 с | 31.193 с |
| Видео | 3 | 33.950 с | 33.276 с |
| **Видео** | **Медиана** | **30.267 с** | **31.193 с** |

| Вход | Полный запрос Debian, медиана | Полный запрос Alpine, медиана | Изменение времени инференса Alpine |
|---|---:|---:|---:|
| Общий WAV | 30.005 с | 27.593 с | -8.3% |
| Видео | 30.807 с | 31.660 с | +3.1% |

Положительное изменение означает больше времени, то есть медленнее. Время полного запроса измерено клиентом; inference включает VAD, признаки, encoder и decoder. Первый запрос каждого контейнера не включён в медианы скорости и доступен в results.json.

FFmpeg в Debian и Alpine различается (5.1.9 и 8.1.2), поэтому общий WAV — основной контроль для сравнения инференса. В предыдущей серии проверено совпадение PCM общего WAV после обработки обоими FFmpeg. Три пары на одном Mac дают ориентир, но не статистическую гарантию производительности на другом хосте.

Все запросы завершились успешно, каждый дал 42 ASR-фрагмента. Уникальных хэшей текста среди 24 запросов: **1**.

Протокол изменён: раньше три повторных запроса шли подряд в одном контейнере, теперь каждый измеряемый запрос идёт после полного прогрева в новом контейнере и порядок образов чередуется. Поэтому разницу между сериями нельзя целиком приписывать перезагрузке или свопу.

Все данные: `summary.json`, `environment.json`, `host-memory.jsonl`, отдельные `results.json`. Тексты, сырые логи и частые выборки ОЗУ сохранены локально и исключены из Git. Основной скрипт: `scripts/benchmark-container.py`, параметр `--runs 1`; порядок и каталоги запусков записаны в environment.json.
