# Debian и Alpine: GigaAM RNNT

Замеры 10 сентября 2026 года. Alpine собран и проверен, исходный Debian-вариант сохранён.

Образ Alpine меньше на **359.7 МиБ (26.5%)**. ОЗУ после загрузки модели меньше на **31.2%**. На видео время инференса изменилось на **+33.2%**, на общем PCM WAV — на **-1.4%** (положительное значение означает медленнее).

Практический результат — экономия диска и ОЗУ. Устойчивого ускорения не подтверждено: повторная серия Debian тоже стала медленнее первой, а на одинаковом WAV различие медиан меньше разброса прогонов.

## Условия

- Исходный коммит: `fa6806112b68ad396da7c7bf5057e243bae6ab7d`. Go-код между образами не менялся.
- Apple M4, 16 ГиБ ОЗУ; macOS 26.6.2; Docker Desktop 4.79.0 / Engine 29.5.3.
- Linux ARM64 без эмуляции amd64; VM: 10 vCPU, около 7,75 ГиБ ОЗУ, ядро 6.12.76-linuxkit.
- Docker.raw находится на внешнем APFS-диске Goida. Одновременно запущен один тестируемый сервис; сборки и другие контейнеры во время замеров остановлены. Остальные приложения macOS не останавливали.
- GigaAM v3 E2E RNNT FP32, 4 потока ONNX, штатные параметры VAD и разбиения. Ревизия модели и SHA-256 входа записаны в `environment.json`.
- Видео «11.9 Линукс для собесов.mp4»: 13 157 439 байт, аудиодорожка 462,016 с. В каждой транскрибации 42 ASR-фрагмента.
- После готовности модели: 12 с простоя, первый полный запрос, затем 3 повторных запроса с паузами 2 с; после них ещё 12 с простоя. Для каждого образа и входного формата создаётся новый контейнер.
- Первый запрос отмечен отдельно: при инициализации сам сервис уже выполняет короткий прогрев графов. Это не тест полностью холодного дискового кэша.
- Последовательность: Debian / видео → сборка и тесты Alpine → Alpine / видео → Debian / общий WAV → Alpine / общий WAV.

## Видео: память, диск и время

| Метрика | Debian | Alpine |
|---|---:|---:|
| Размер образа, включая модели | 1359.1 МиБ | 999.4 МиБ |
| ОЗУ: простой после загрузки модели | 1307.6 МиБ | 899.0 МиБ |
| ОЗУ: простой после запросов | 1495.6 МиБ | 1027.1 МиБ |
| Пик ОЗУ при распознавании, выборка | 1504.3 МиБ | 1041.6 МиБ |
| RSS процесса: простой после загрузки | 1300.9 МиБ | 916.2 МиБ |
| Пик RSS процесса при распознавании, выборка | 1421.8 МиБ | 1033.0 МиБ |
| Записываемый слой после очистки | 0 байт | 0 байт |
| Первый запрос: инференс | 28.330 с | 28.661 с |
| Повторные: медиана инференса | 22.154 с | 29.500 с |
| Повторные: медиана полного запроса, клиент | 22.703 с | 30.027 с |
| RTF по медиане инференса | 0.04795 | 0.06385 |

ОЗУ в таблице — `memory.current − inactive_file` из cgroup, то есть рабочий набор по подходу Docker stats. RSS измеряется отдельно по `/proc/1/status`. Выборка примерно каждые 0,5 с плюс время `docker exec`; короткие пики могут быть пропущены. Это память контейнера, не суммарная память Docker VM. Все исходные cgroup-значения и VmHWM сохранены в локальных `samples.json`.

Размер образа — сумма несжатых слоёв `docker image inspect .Size`; общий базовый слой между образами хранится один раз. Это не размер скачивания из registry и не прирост физического размера Docker.raw. Нулевой записываемый слой получен после очистки запросов: во время обработки дополнительно хранятся загруженный файл и WAV.

## Контроль на одном PCM WAV

Debian использует FFmpeg 5.1.9, Alpine — FFmpeg 8.1.2. PCM после декодирования исходного видео не совпал побайтно; SHA-256 сохранены в `debian/pcm.sha256` и `alpine/pcm.sha256`. Поэтому дополнительно один раз подготовлен PCM16 mono 16 кГц WAV в Debian, и этот одинаковый файл передан обоим сервисам. Проверка подтвердила совпадение PCM после повторного преобразования этого WAV в обоих образах.

| Инференс на общем WAV | Debian | Alpine |
|---|---:|---:|
| Первый | 29.421 с | 24.899 с |
| Повторный 1 | 30.441 с | 29.288 с |
| Повторный 2 | 25.956 с | 25.919 с |
| Повторный 3 | 28.519 с | 28.129 с |
| Медиана повторных | 28.519 с | 28.129 с |

Разброс прогонов заметен: это измерения на одном Mac с Docker VM и работающими приложениями macOS, а не статистическая гарантия для другого сервера. Сравниваются два готовых стека: разные libc, компиляторы C/C++, сборки ONNX и FFmpeg. Приписывать всю разницу только musl нельзя.

## Корректность и состав сборки

- Число уникальных SHA-256 текста среди всех 16 запросов: **1**. Тексты всех запросов совпали побайтно.
- `go test ./...` и `go vet ./...` прошли в Alpine test stage.
- `TestNativeVAD`, `TestGolden` (RNNT и CTC, речь/тишина/короткая запись), `TestNativeCancellation` (RNNT и CTC) прошли с собранной musl-библиотекой.
- `ldd` подтвердил musl для Go-бинарника и ONNX. Рабочий образ Alpine 3.24.1 не содержит glibc loader, Python и GCC. Вывод: `alpine/runtime.txt`.
- ONNX Runtime 1.29.0 собран из архива тега v1.29.0 с проверкой SHA-512, Release, общий CPU runtime без сокращения операторов. FlatBuffers собран с `FLATBUFFERS_LOCALE_INDEPENDENT=OFF` для musl.
- Встроенные C++ unit-тесты самого ONNX Runtime не собирались. Проверена платформа linux/arm64; amd64 не проверялась.
- Модели взяты из локального build-context для исключения повторного скачивания ~0,9 ГБ. Все файлы проверены по размерам и SHA-256 текущего manifest.json. В обычной сборке их скачивает штатный model-files stage.

## Сборка и воспроизведение

Первичная сборка заняла около 18 мин 38 с, включая загрузку зависимостей и паузу на изменение параллелизма: сначала 2 процесса, затем 4, с продолжением из кэша BuildKit. По умолчанию в Dockerfile остаются 2 процесса. Кэш объектных файлов и зависимостей ONNX после сборки: около 307,2 МБ (docker buildx du); исходники, APK-слои, Go-кэш и тестовый образ занимают место дополнительно. Это не часть рабочего образа.

Суммарный build-кэш Docker по `docker system df` вырос с 4,098 до 8,105 ГБ за эксперимент, включая сборочные и тестовые этапы. Поэтому меньший рабочий образ не означает меньший суммарный расход диска при первой компиляции из исходников. Кэш находится на Goida и сохранён для повторных сборок. Эти числа — учёт Docker, а не измерение прироста физического Docker.raw; исходные итоги записаны в `disk-summary.jsonl`.

```bash
docker build -t gigaam-service:bench-debian .
docker build -f Dockerfile.alpine --build-arg ORT_BUILD_JOBS=4 -t gigaam-service:alpine .
python3 scripts/benchmark-container.py --image gigaam-service:bench-debian \
  --video /absolute/path/recording.mp4 --output bin/benchmarks/debian
python3 scripts/benchmark-container.py --image gigaam-service:alpine \
  --video /absolute/path/recording.mp4 --output bin/benchmarks/alpine
docker build -f Dockerfile.alpine --build-arg ORT_BUILD_JOBS=4 --target test .
```

Compose: `docker compose -f compose.yaml -f compose.alpine.yaml up -d --build`.

Машиночитаемые результаты: `summary.json`, `environment.json`, `tests.json` и `results.json` в каталогах `debian`, `alpine`, `debian-wav`, `alpine-wav`. Сырые логи, выборки памяти, WAV и тексты сохранены локально и исключены из Git.

Источники параметров сборки: [официальная документация ONNX Runtime](https://onnxruntime.ai/docs/build/inferencing.html), [рецепт Alpine aports](https://github.com/alpinelinux/aports/blob/master/community/onnxruntime/APKBUILD).
