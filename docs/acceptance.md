# Проверки реализации

Базовые проверки ниже выполнены 09.09.2026 на macOS arm64, Apple M4, 16 GiB RAM, Go 1.26.1, ONNX Runtime 1.22.0. Они сохранены как исторический результат; текущий рантайм — 1.29.0, проверка обновления описана отдельно. Параметры производительности целевого Linux-сервера ещё не определены.

## Обновление ONNX Runtime до 1.29.0

09.09.2026 проверены SHA-256 официальных архивов macOS arm64, Linux amd64 и arm64. Go-обвязка v1.22.0 оставлена: новая библиотека успешно предоставляет используемый C API v22. Стартовый лог работающего сервера подтверждает `version=1.29.0`.

- `go test -race ./...` и `go vet ./...` прошли.
- Нативные RNNT/CTC, VAD, окна 1/20/30 секунд и отмена encoder Run прошли на 1.29.0.
- Эти же нативные тесты отдельно прошли в Linux arm64 / Debian Bookworm внутри Docker: обе модели, 6 эталонов, длинная запись и отмена. Для проверки использован Go-слой сборки с официальной Linux-библиотекой 1.29.0 и отключённой сетью.
- Полный образ `gigaam-service:dev` собран для Linux arm64. HTTP-тест MP4 в готовом образе с `--network none`, локальным кэшем моделей и непривилегированным UID 501 прошёл: версия 1.29.0, точный текст, очистка файлов. UID выбран для доступа к смонтированным файлам Mac; штатный пользователь образа остаётся 10001. Тестовый контейнер остановлен, основной сервер продолжает работать напрямую на macOS. Linux amd64: архив и SHA-256 проверены, запуск образа на этой архитектуре не проверялся.
- Все 6 эталонных транскрипций совпали с существующим независимым эталоном на ORT 1.22.0. `scripts/requirements-reference.txt` сохраняет исходную версию эталонного окружения; она не используется сервером. Эталонные тексты не перегенерировались при обновлении.
- Обе модели корректно обработали 64,11 секунды речи с 11 повторениями тестовой фразы.
- После перезапуска сервера HTTP-запросы с MP4 и длинным WAV дали точный ожидаемый текст; временные файлы удалены. Измерения сохранены в [runtime-1.29.0-validation.json](runtime-1.29.0-validation.json).
- RNNT обработал тестовый WAV длительностью 64,11 с за **1,619 с**, из них инференс — **1,568 с**, RTF — **0,0253**. Ранее тот же файл на 1.22.0 обрабатывался за 5,799 с при тех же intra-op=2 и concurrency=1. Это отдельные локальные замеры при фоновой нагрузке, не контролируемый бенчмарк и не SLA. Часовой прогон ниже относится только к 1.22.0.


## Подтверждено

- `go test -race ./...`, `go vet ./...`, `git diff --check`.
- HTTP: обязательные/неподдерживаемые поля, авторизация, 413, 422, 429, storage 503, таймаут, отключение, остановка; health остаётся доступным независимо от готовности модели.
- Реальный TCP-тест: незавершённое медленное тело не задерживает 401/429, загрузка завершается по read deadline.
- Файлы отсутствуют до записи успешного HTTP-заголовка; отказ удаления блокирует новые запросы, повторная очистка восстанавливает работу; остатки после аварии удаляются на старте.
- Текущий нативный вызов при отмене удерживает слот до возврата; тест имитирует медленный native call и проверяет отсутствие раннего освобождения. Немедленное прерывание ORT не заявляется. Реальный тест отмены 30-секундного encoder Run на M4 вернулся через 3,52 с для RNNT и 2,84 с для CTC при отмене через 10 мс после начала вызова; это локальное измерение при фоновой нагрузке.
- TLS-загрузчик: валидный файл, испорченный кэш, ошибочная сумма/размер, частичный файл, таймаут; манифест содержит фиксированные HTTPS-ревизии и SHA-256.
- Реальный FFmpeg: WAV, MP3, FLAC, OGG/Opus, AAC, MP4, WebM; неправильный файл, видео без аудиодорожки, превышение длительности, отмена и запрет плейлиста.
- Silero VAD с нативной ONNX Runtime: корректные формы состояния, обработка тишины.
- Полные FP32 RNNT и CTC: загрузка, прогрев, распознавание, окна 1/20/30 секунд. Веса проверены по SHA-256.
- Официальный эталон: обе модели, 5,828-секундная синтетическая русская фраза, её первые 2 секунды и секундная тишина. Все 6 транскрипций совпали точно, включая пунктуацию. Максимальная абсолютная ошибка log-mel на этих записях — **0,001688**, у тишины — 0.
- Независимый синтетический Torch-эталон признаков включён в обычные Go-тесты. Численный допуск и поведение на почти нулевой энергии описаны в [models.md](models.md).
- 64,11 секунды речи (11 повторений исходной фразы): обе модели вернули все 11 фраз строго в ожидаемом тексте. Этот тест выявил и помог исправить чрезмерное удаление одинаковых предложений на перекрытиях и разрезание слов на границах.
- Настоящий HTTP-сервис с RNNT: WAV, MP3 и видео MP4 дали ожидаемый текст; JSON/text, `/v1/models`, offline cache и отсутствие временных файлов после ответа проверены.
- `docker compose config --quiet` проходит. Две попытки сборки Docker остановились на сети Docker Hub: таймаут метаданных `debian:bookworm-slim`, затем TLS handshake timeout при запросе `golang:1.26.1-bookworm`. До компиляции внутри образа сборка не дошла.

## Производительность

Локальный короткий прогон: 64,11 секунды синтетической речи обрабатывались примерно за 5–7 секунд, ONNX intra-op=2, inter-op=1, concurrency=1. Это ориентир на тестовом Mac при фоновой нагрузке, не SLA и не замер на целевом Linux CPU.

Финальный часовой HTTP-прогон RNNT: 3600 секунд синтетической речи, **281,51 секунды** полного запроса (RTF **0,0782**), **1 838 546 944 байта / 1,71 GiB** максимального RSS по `getrusage`, intra-op=2, inter-op=1, concurrency=1. Сэмплирование RSS раз в секунду подтвердило ограниченную память: в конце запроса около 973 MiB. Ответ точно совпал с повторённым исходным текстом: 617 полных фраз и начало 618-й, на которой обрезается часовой WAV; рабочий каталог был пуст до получения результата клиентом; тестовый процесс штатно остановлен. Повторения позволяют проверить длинный синхронный запрос, но не заменяют разнообразный часовой корпус.

Контейнерные CPU/RAM-лимиты в этом замере не применялись: сервис запущен нативно на Mac, одновременно выполнялись другие проверки. Поэтому цифры не являются производственным SLA. Полный Go+VAD+ASR маршрут измерен через HTTP; отдельный чистый ASR benchmark на целевом Linux ещё требуется.

## Проверки перед производственным релизом

1. Завершить Docker build и запустить образ на целевом Linux amd64/arm64. Проверить пустой volume, затем повторный запуск с тем же кэшем и отключённой сетью, смену RNNT/CTC, нехватку места и прерванное скачивание.
2. Сравнить реальные, разрешённые к использованию русские записи разных дикторов с соответствующим официальным FP32-примером. Текущие эталоны используют официальные признаки/декодеры с зафиксированным готовым ONNX-экспортом; независимая переэкспортировка PyTorch-чекпоинтов и побитовое воспроизведение стороннего экспорта не выполнены.
3. Проверить разнообразные записи часовой длины, непрерывную речь, слова возле границ, музыку, тишину, очень короткие файлы. Синтетический повтор одной фразы не заменяет такой корпус.
4. Измерить отдельно ASR и весь HTTP-запрос: CPU/инструкции, лимиты контейнера, потоки, ревизии моделей, RTF, peak RSS. Измерить время завершения текущего encoder Run при отмене; оно зависит от окна, CPU и числа потоков. Настроить Docker stop grace на основании этого замера.
5. Прогнать длинный запрос через фактический ingress/reverse proxy, обрыв во время загрузки и выдачи результата, SIGTERM и принудительное завершение контейнера. Проверить временные файлы прокси и startup cleanup после рестарта.
6. Запустить пользовательский сценарий с конкретной закреплённой версией OpenAI-клиента. HTTP-подмножество реализовано и curl проверен; полный OpenAI API не реализуется.

Непройденные пункты не обозначаются как выполненная приёмка. Статус Docker healthcheck означает только доступность HTTP-процесса и не заменяет эти проверки.
