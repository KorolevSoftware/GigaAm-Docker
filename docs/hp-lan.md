# Доступ к GigaAM на мини-ПК из домашней сети

Адрес работающего Alpine-сервиса: **http://192.168.0.36:8080**. Файлы можно отправлять с Mac и других устройств домашней сети напрямую, без SSH-туннеля. Для API по-прежнему нужен ключ; текущий лимит загрузки на HP — **15 ГиБ на файл**, ONNX использует **2 потока**.

## Отправка файла с Mac

Укажите существующий путь на Mac. Ключ читается по SSH из `.env` мини-ПК и передаётся curl через stdin, без вывода на экран и записи в командную строку:

```bash
gigaam_file='/полный/путь/к/видео.mp4'

ssh dmitry@192.168.0.36 \
  "sed -n 's/^GIGAAM_API_KEY=/Authorization: Bearer /p' ~/gigaam-service/.env" |
  curl --silent --show-error --fail-with-body --max-time 3600 \
    --header @- \
    http://192.168.0.36:8080/v1/audio/transcriptions \
    --form "file=@\"$gigaam_file\"" \
    --form 'model=gigaam-v3-e2e-rnnt' \
    --form 'response_format=text' \
    --output transcript.txt
```

Внутренние кавычки в `file=@\"...\"` нужны curl для путей с запятыми; внешние сохраняют пробелы при обработке командной оболочкой. Текст появится в `transcript.txt`. При ненулевом коде завершения curl этот файл может содержать JSON с ошибкой API. SSH здесь используется только для чтения ключа: сам файл идёт напрямую по HTTP на IP мини-ПК. Если ключ уже хранится у клиента, получать его по SSH при каждом запросе не требуется.

Проверка HTTP без ключа:

```bash
curl --fail http://192.168.0.36:8080/healthz
```

Готовность модели проверяется авторизованным `GET /v1/models`; `healthz` подтверждает только работу HTTP. Соединение внутри домашней сети использует HTTP. Доступ из интернета и проброс портов роутера не настроены.

## Что настроено на HP

В `~/gigaam-service/compose.local.yaml` добавлен второй адрес публикации порта:

```yaml
services:
  asr:
    ports:
      - "192.168.0.36:${GIGAAM_PORT:-8080}:${GIGAAM_PORT:-8080}"
```

В `.env` мини-ПК:

```dotenv
COMPOSE_FILE=compose.yaml:compose.alpine.yaml:compose.local.yaml
```

Основной `compose.yaml` продолжает публиковать `127.0.0.1:8080`; объединение файлов сохраняет оба адреса. Поэтому localhost и прежний SSH-туннель работают. Локальный файл исключён из Git; общий default репозитория остаётся доступным только через loopback. Firewall и роутер не менялись. Если DHCP изменит IP мини-ПК, обновите адрес в локальном файле; для постоянного URL можно закрепить текущий адрес в DHCP-настройках роутера.

Последующие команды на HP выполняйте из `~/gigaam-service`, чтобы Compose прочитал `.env` и все три файла:

```bash
sudo docker compose logs -f asr
# Применить настройки без сборки и загрузки образа:
sudo docker compose up -d --no-build --pull never asr
```

Для сборки нового кода: `sudo docker compose up -d --build`. Если перечислять `-f` вручную, нужно указать все три файла, иначе локальная публикация порта исчезнет.

## Текущие настройки и свободное место

После очистки тестовых образов и неиспользуемого Docker build cache на рабочем разделе свободно около 24 ГиБ. Рабочий Alpine-образ, резервный Debian и подготовленная библиотека `.onnxruntime/amd64/` сохранены. Контрольные суммы библиотеки проверены.

В `.env` мини-ПК установлены:

```dotenv
GIGAAM_ONNX_THREADS=2
GIGAAM_MAX_FILE_BYTES=16106127360
```

Проверка четырёх потоков на записи 588,6 с дала 261,8–262,1 с на запрос против 249,6 с при двух потоках. По просьбе пользователя возвращены два потока.

Лимит загрузки снижен до 15 ГиБ. Ограничение длительности записи удалено из кода и конфигурации; таймаут обработки — 10 часов. Перед загрузкой требуется около 15,5 ГиБ свободного места в `/work` (максимальный исходник и резерв 512 МиБ). Для WAV дополнительно нужно около 115,2 МБ на час записи. Размер WAV при конвертации ограничен свободным местом за вычетом резерва; при его исчерпании запрос возвращает `storage_unavailable`, без частичной транскрипции.

## Первоначальная проверка LAN 10 сентября 2026

На HP подтверждён интерфейс `enp1s0`, адрес `192.168.0.36/24`. Перед применением активных запросов не было, `/work` был пуст. Контейнер пересоздан с прежним образом, без сборки; изменилась только публикация порта. FP32 RNNT, два потока инференса и лимит 1 ГиБ сохранены.

С Mac напрямую по LAN: `/healthz` и авторизованный `/v1/models` вернули 200, защищённые модели и транскрибация без ключа — 401. WAV на 30 секунд распознан за 12,803 с; все 565 символов совпали с предыдущей проверкой. Старый туннель `127.0.0.1:18082` также прошёл авторизованную проверку. Отдельно проверен curl с заголовком через stdin и именем файла, содержащим пробел и запятую: текст совпал. Результаты: [lan-results.json](../benchmarks/hp-6405u-alpine/lan-results.json).
